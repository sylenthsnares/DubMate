## What blocks a release now

1. **Packaged media dependency — fixed.** The first v2 test build, [43144624703](https://github.com/sylenthsnares/DubMate/actions/runs/43144624703), passed full CI and both installer builds, but the actual Windows payload omitted FFprobe. Its embedded Python measured a valid video as 0 seconds on a clean PATH. The replacement Windows installer includes FFprobe and measures that fixture as 20 seconds; the staged-runtime guard also passes with a one-second video. The following run exposed a macOS read-only duplicate copy; FFprobe is now staged once outside the architecture loop with a replaceable copy. Final [run 43193764167](https://github.com/sylenthsnares/DubMate/actions/runs/43193764167) passed full CI, both frozen-runtime guards and both installer builds.
2. **Reliable test baseline.** `pack_loader.init_pack_dirs()` always adds the real default and CWD `Packs/` even with a temporary configured folder. A test on this checkout transcoded real `.ogv` scene videos. The full run was deliberately stopped; the update-path test also timed out after 90 seconds. A clean source checkout/CI excludes the local media and is the immediate validation route; the local runner isolation issue remains to fix.
3. **Migration test reliability.** First isolated `test_data_home.py` run: 37/38 passed, read-only copy case failed. A standalone probe, an isolated diagnostic run (38/38), and an unmodified isolated repeat (38/38) then passed. Cause is not established. This is an inconsistent test result, not evidence of confirmed data loss. Exercise real cross-drive/readonly upgrade behavior before release.
4. **Windows build environment.** `cargo test --offline` cannot compile here: `link.exe` is missing; standard Visual Studio Installer discovery also found no installation. Use Windows GitHub Actions, or provision MSVC before local builds.
5. **Release metadata.** Main was still 1.1.3 everywhere with an Unreleased changelog. This release branch prepares 2.0.0 and a dated changelog. Use `build_only=true` until the release candidate is tested; ordinary manual dispatch on old metadata can rebuild an existing release.
6. **Installed-app acceptance.** Fresh install and 1.1.3 upgrade, old-room takes, retained Pack Builder, tunnel guest recording, playback/export and restart/resume must work in the EXE. Unchecked PR checklists are still unverified, even where their code is merged.

GitHub's private-reporting switch also needs enabling or SECURITY.md needs an alternative contact. It was read only, not changed in this review.

## Release sequence

1. Finish v2.0.0 metadata checks and validate from a clean checkout with fixture packs only.
2. Build Windows/macOS installers using `Release` with `build_only=true` on the exact candidate commit. This is an existing supported route from #11.
3. Inspect the built Windows installer and run the installed-app acceptance checks, especially #19, #24, #29 and #32. Record failures and fix the demonstrated causes.
4. Publish v2 only after checks pass. The current workflow requires the Windows EXE, macOS DMG and app-bundle ZIP before its publish job exposes the release.

Backlog items such as host hand-off, durable pending uploads, unfinished-builder-session persistence and engine-to-engine scene import are not prerequisites for producing a working v2 installer. They should stay explicit rather than being mistaken for fixes already shipped.
